# 元音训练与音色分析 —— 设计与实现

> 状态：**已实现**（2026-11-19/20）。
> 讲的是「怎么做的」和「踩了哪些坑」。
> 功能层面的说明在 README。

---

## 1. 做了什么

App 现在有两个页面（底部标签切换）：

| 页面 | 回答的问题 |
|---|---|
| **监测** | 我现在多高？（原有的 f0 曲线） |
| **训练** | 我这个音**准不准、稳不稳**？ |

训练页三块内容：

1. **元音图** —— 你在元音空间里的位置，和目标元音的距离
2. **稳态度** —— 帧与帧之间的抖动
3. **音色轴** —— 薄虚 ↔ 厚实（需要个人基准）

### 为什么单独一页

不只是「主页面挤」：

- **数据不同**：监测画 f0 曲线，训练要 F1/F2 轨迹和音色轴
- **交互不同**：监测是「打开就看」，训练是「选目标 → 练 → 看反馈」，
  需要参照物
- **性能**：LPC 分析只在训练页跑，监测页照旧轻量

## 2. 整体流程

```
麦克风 ─48kHz─► FIR 降采样 ─16kHz─┬─► YIN ──► f0 曲线（监测页）
                                  │
                                  └─► LPC ──► 共振峰 ─┬─► 元音图
                                                       ├─► 元音识别
                                                       ├─► 稳态度
                                                       └─► 音色轴
```

**两条支路共用同一份 16 kHz 数据**，各自维护滑动窗口
（窗口 1024 = 64 ms，跳帧 256 = 16 ms），所以时间对齐，
界面上的读数能直接叠着看。

LPC 分析**默认不开** —— 监测页不需要，只在训练页启用。

## 3. LPC 求共振峰

### 3.1 为什么用求根，不是在包络上挑峰

周期声源的梳状结构会让包络上出现一堆几乎等高的起伏。
实测 `/a/` 的 F2 就是个只有零点几 dB 的小凸起 —— 按「最高峰」选会
直接跳过它选到 F3。

求根没有这个问题：每个根就是一个独立的共振候选。

### 3.2 求的是**反转多项式**

LPC 多项式 `A(z) = 1 + a₁z⁻¹ + … + aₚz⁻ᵖ`，令 `w = z⁻¹`，
它的根在**单位圆外**（稳定极点的倒数的倒数），
数值条件很差 —— Durand-Kerner 的初值在圆上、根在圆外，
经常收敛不了。真机上表现为大部分帧一个根都求不出来。

反转多项式 `q(w) = wᵖ + a₁wᵖ⁻¹ + … + aₚ` 的根**就是极点本身**
（`|z| < 1`，在单位圆内），条件好得多。

### 3.3 参数是标定出来的

`LpcSweepTest` 扫了预加重 0–0.97 × 阶数 12–20 × 两种提取方法，
用 6 个**共振峰已知**的合成元音（a/i/u/æ/ɛ/ɔ）算平均误差。

| 提取方法 | 预加重 | 阶数 | 平均误差 |
|---|---|---|---|
| 求根 | 0.7 | 12 | 37 Hz |
| 求根 | 0.3 | 12 | 38 Hz |
| 求根 | **0.7** | **16** | **63 Hz** |
| 挑峰 | 0.97 | 16 | 75 Hz |

### 3.4 但阶数要看**真机**，不是只看合成

这是最关键的一条：

| | 12 阶 | 16 阶 |
|---|---|---|
| 合成元音（干净信号） | 38 Hz ✓ | 63 Hz |
| **真机**（手机麦 + 房间） | **F2 整个消失** ✗ | 三峰齐全 ✓ |

真信号比合成信号「脏」—— 房间反射、麦克风染色、蓝牙链路，
低频结构更杂，要多几个极点才拟合得出三个共振峰。

**所以取 16**：宁可多一点极点（后面有频带/带宽过滤兜底），
也不能丢共振峰。

### 3.5 两道过滤，两个坑

**稳定性**：LPC 拟合出的中间共振峰有时会落到单位圆外一点点。
一刀切丢掉的话 F2 经常整个消失。放宽到 `|z| ≤ 1.05`。

**带宽**：真信号里的共振峰会被手机麦、蓝牙链路和房间混响**抹宽**。
实测 `/a/` 的 F2 根带宽 484–510 Hz。

| 上限 | 结果 |
|---|---|
| 400 Hz | `/a/` 的 F2 被丢掉 ✗ |
| **520 Hz** | 两头都不越界 ✓ |
| 700 Hz | 伪根也放进来，把 `/i/` 的 F2 顶掉 ✗ |

> 伪根是阶数比实际共振峰多时，极点去拟合噪声产生的。
> 它们有模有样但不是共振峰 —— 带宽比真的共振峰宽，
> 所以带宽上限卡在 520 刚好把它们挡住。

## 4. 元音识别

### 4.1 归一化：折算到标准声道长度

绝对共振峰频率因人而异 —— 声道长的人所有共振峰都低。
语音学的标准做法是折算到 17.5 cm 的标准男性声道，
这样所有人的元音图在同一个坐标系里。

**声道长度怎么估**：不要求用户知道，而是用录基准时念 `/a/` 的
实测 F1 反推 —— F1 测出来低 = 声道长。

> 这个公式的方向一开始写反了（`normalized / measured`），
> 被单元测试抓到的。

### 4.2 距离度量

```
距离 = sqrt(ΔF2² + (1.4·ΔF1)²)
```

F2 的权重 1.4 倍 —— 舌位变化比开口度更容易被听出来。

「认得出」的阈值：180（归一化 Hz）。

## 5. 稳态度

测的是**帧与帧之间的抖动**，单位换算成**音分**（和听感一致）。

两个坑，都被单元测试抓到了：

- **音分差要取绝对值**。抖动是双向的，不取绝对值的话正负差值
  互相抵消，中位数 ≈ 0，看起来比实际稳得多。
- **F1/F2 的抖动取平均，不取 min**。取 min 的话只要有一个维度稳
  就完全掩盖了另一个维度的抖动 —— 实测抖动 ±60 Hz 的信号会拿满分。

映射：抖动 ≤ 10 音分 → 1.0（几乎不动）；≥ 120 音分 → 0.0。

## 6. 音色轴

把「虚实 / 前共振 / 后共振 / 厚薄」合成**一条轴**（−1..+1）。

这些词在频谱上是高度相关的，分开做几个指标用户会看到互相
矛盾的数字。

两个子特征，各自相对**个人基准**标准化后加权：

```
轴位置 = 0.6 × z(谱倾斜) + 0.4 × z(F1)
```

### 为什么必须用个人基准

「厚」没有绝对标准：男声天生低频多、喉腔大小不同、
麦克风频响 + 蓝牙染色也不同。任何固定阈值都是错的。

做法：录一段 `/a/` 作为基准，之后显示「比你的基准偏亮还是偏暗」。

## 7. 真机验证

用**合成的已知元音**（`tools/gen_vowel.py`：Rosenberg 声门源 +
三段共振器）经 Mac 喇叭播放、手机麦采集：

| 元音 | 期望 F1/F2 | 实测（Note 20 Ultra） | 识别 |
|---|---|---|---|
| /a/ | 730 / 1090 | 724 / 1401 | 「啊」✓ |
| /i/ | 270 / 2290 | 210 / 2375 | 「衣」✓ |
| /u/ | 300 / 870 | 257 / 810 | 「乌」✓ |

`/a/` 的 F2 差 311 Hz 是**测试链路的声学限制**：
笔记本喇叭 → 房间 → 手机麦这条路上，1100–1300 Hz 的包络只差 2 dB，
峰位本就模糊。干净合成信号上同一配置是 723/1060（误差 7/30 Hz）。

**这说明真机上的精度下限由采集链路决定，不是算法。**

## 8. 真机验证：一次**结论完全错了**的排查

> 这一节记录的是一次自我纠错 —— 结论是错的，
> 而且错的方向很典型，值得留着。

### 当时的结论

在 Note 20 Ultra 上用「Mac 喇叭 → 房间 → 手机麦」测，
`/a/`（期望 F1=730 F2=1090）报成 **F1 724 / F2 2407**。

当时的判断是：

> F2 偶尔会整个消失（共振峰被噪声淹没），
> 按频率取第二个根拿到的其实是 F3。
> 笔记本喇叭放不出 300 Hz 的共振峰，
> 到达麦克风的信号里这些共振峰已经不存在了。
> **算法在这种情况下报出的是「信号里实际有的东西」，不是它算错了。**

为了"证明"这个结论，还写了个单元测试：
拿干净的合成 /u/ 加上低频滚降和噪声，
看 F1 会不会偏离 —— 确实偏离了（310 → 387）。

于是又花了好几轮去改算法：
包络判据、频带分配法、伪根过滤……全都试过、都失败了。

### 真相：是**测试信号**不真实

有人提了个问题：

> 「有没有可能是 F2 检测是对的，你的标定错了？」

这才去**独立**验证 —— 不走 App 的代码，用纯 Python 的 Goertzel
直接分析合成的 WAV：

```
720 Hz    0.0 dB     ← F1
1080 Hz  -26.2 dB    ← F2
```

**合成的 F2 比 F1 低 26 dB。** 真实的元音不是这样 ——
三个共振峰的高度是接近的（F1 最强，F2 低 5–15 dB，F3 再低一点）。

不真实的信号经过喇叭和房间之后，F2 直接掉进噪声底，
LPC 拟合噪声、在 F3 附近产生一个伪根 —— **信号的问题，不是算法的问题。**

### 修好之后

在级联之后加一道**峰值均衡**（把三个共振峰拉到真实比例）：

| | F2 相对 F1 | /a/ 实测 F1/F2 | 误差 |
|---|---|---|---|
| 修之前 | **−26 dB** | 724 / 2407 | F2 差 1300 Hz ✗ |
| 修之后 | **−8 dB** | **735 / 1159** | **F2 差 69 Hz ✓** |

F2 的误差从 1300 Hz 降到 69 Hz。**算法一直是对的。**

### 为什么级联会这样

朴素的「声门源 → 级联三个共振器」里，
第二个共振器吃的是**第一个共振器整形之后**的信号，
而第一个（F1=730, BW=60）的裙边在 1090 Hz 处压了约 15 dB。

真实声道的共振峰峰值增益取决于该处的反射和损耗，
不是级联里"前一级把后一级喂弱了"那么简单。
所以修法不是调带宽（试过，没用），而是**级联完做一次 EQ**。

### 教训

**验证工具本身要先被验证。**

之前所有的单元测试都是「合成信号 → 分析 → 对比参考值」，
看起来是自洽的，但**信号和参考值来自同一张表**，
所以测的其实是"实现和合成器一致"，不是"符合真实人声"。

现在加了三条防线：

1. `tools/gen_vowel.py --check` —— 独立测量输出频谱，打印三个峰的相对电平
2. `VowelSynth`（测试用的共享合成器）—— 同样做峰值均衡
3. `syntheticSpectrumLooksLikeRealVoice` 测试 —— 守住「峰之间不能差 15 dB 以上」

第 3 条是关键：**它守的是测试信号本身**。
以后谁改了合成器，这条测试会立刻发现。

### 剩下的真实限制

`/u/`（F1=300, F2=870）在这条测试链路上**仍然测不准** ——
因为 300 Hz 和 870 Hz 在笔记本喇叭的响应里太弱。

验证：把同样的 /u/ 抬到 500/1150/2500，立刻测得
**F1 374 / F2 1092**（误差 58 Hz），识别「乌」✓

所以这条链路的**频率下限**大概在 400–500 Hz。
真机使用时手机在嘴边，信噪比高得多，不受这个限制。

## 9. 这一页到底该干什么（重要设计决定）

> 这一节记录的是**目标本身**的重新定义 ——
> 之前把这一页做成了「元音识别器」，方向就错了。

### 之前做错了什么

原设计：图上画几个标准元音的黑点，用户选一个目标，
把自己的点移到那个点上就算练好了。

**两个都错**：

1. **元音图本身的用途是区分元音身份**（舌位前后高低），
   不是衡量女性化程度。
2. 女性化的目标**不是**「把 /a/ 念成标准 /a/」。

### 真正���目标

> **在保持元音可辨认的前提下，整体把共振峰空间往前、往上抬**
> （等效更短声道、更靠前共鸣），
> 同时搭配合适 F0、稳定发声、语调、嗓音质量。

这是一句关于**空间位移**的话，不是关于某个点的。

所以目标应该长这样：

- **目标是一个区域，不是一个点** ——
  真实说话人的共振峰散布很宽，女性元音是一片分布，
  落在区域里就算达标
- **元音身份和女性化目标是分开的两件事** ——
  界面上必须分成两行，不能混在一起
- **给出的是「往哪调」，不是「你错了」** ——
  「F2 偏低 → 舌位再往前一点」，比一个笼统的距离有用得多

### 现在的设计

```
目标：把共振峰空间往前、往上抬，同时保持元音可辨认

[图表：每个元音一片目标区域云，当前目标高亮 + 当前位置]

发「啊」，把点移进目标区                    目标 F1 803 / F2 1308
元音身份                              你在发「啊」
F1 偏低 88                          F2 ✓ 达标
共振峰前移   F1 -2%  F2 14%   （目标 +10% / +20%）
再调一点：嘴再张开一些
[保持进度条]  已保持 2.3 秒 / 目标 10 秒
```

**目标值怎么来的**：从参考声道（归一化到 17.5 cm）的元音位置出发，
按女性化系数换算 —— F1 × 1.10（往上抬）、F2 × 1.20（往前移），
约等于声道缩短 8–10%。

**目标区域多大**：F1 ±80 Hz、F2 ±180 Hz。
用**绝对值**而不是百分比 —— 跨说话人的变异在绝对值上更接近
（归一化之后 F1 散布约 ±60–90 Hz、F2 约 ±150–200 Hz）。
用百分比的话，/衣/ 的 F1 只有 297 Hz，12% 才 ±36 Hz —— 比音分还紧，
根本进不去；/乌/ 的 F2 才 1044 Hz，12% 是 ±125 Hz —— 松得没意义。

### 归一化不再显示

之前页面顶上写「声道 17.5 cm（折算到…）」。

**归一换算是跨人对比的科研工具，不是初学者训练目标** ——
用户看不懂这个换算，也不知道该拿它怎么办。
它是背后的计算细节，不该出现在训练界面里。

现在界面上只说人话：「把共振峰空间往前、往上抬」。

### 已知限制：身份和女性化是纠缠的

识别用的是**参考声道**里的元音位置，而女性化目标在它前面 ——
声音往前挪之后，识别标签会跟着漂。

实测：目标位置的 /æ/（726, 2064）会被认成 /诶/，
目标位置的 /哦/（627, 1008）会被认成 /啊/。
主要的 /a/ /i/ /u/ 没问题。

试过三种改法，都有更糟的副作用：

1. **把参照位置换成目标空间** —— 男性位置的 /i/（270, 2290）
   离目标位置的 /诶/ 更近，被认成 /诶/。
2. **识别时允许整体缩放** —— /啊/ 和 /哦/ 的 F1:F2 比例几乎一样
   （1.49 vs 1.47），任何缩放都能把一个套到另一个上，
   噪声一大标签就在两者间闪（实测 60 帧里闪 13 次）。
3. **用目标元音来估缩放因子** —— 目标本身估错了的时候，
   整个识别都跟着歪。

**根因是元音图本身的局限**：/啊/ 和 /哦/ 的区别主要在圆唇
（影响 F3 和频谱倾斜），不在 F1/F2 上。
只靠 F1/F2 分不出这两个 —— 这是元音图的天花板。

要解决它得引入别的信号：F3、频谱倾斜、或者 F0。
记在 TODO 里。

## 9. 踩过的坑

### 8.1 预加重和阶数要一起标定

单独看任何一个都不够 —— 阶数 12 在合成信号上最好，
但真机上会丢 F2；预加重 0.97 在合成信号上会把 `/i/` 的 F1 压没。

### 8.2 测试信号要用声门流的**导数**

唇端辐射是 +6 dB/oct。拿声门流本身（频谱 −12 dB/oct）去级联的话，
`r[1]/r[0]` 会接近 1，Levinson 的反射系数直接爆掉，
递推发散、系数变成回文结构 —— 看起来像 LPC 写错了，其实是信号造错了。

### 8.3 反射系数必须钳位

`|m| < 1` 否则预测误差 `e` 变号，后面所有系数全错。
真机上遇到静音帧、突发噪声就会这样。

### 8.4 合成元音的频谱比例（最贵的一个坑）

**信号不真实 → 验证结论完全错 → 照着错结论改算法。**

详见第 8 节。教训是：**验证工具本身要先被验证**，
而且要独立验证（不走被测代码）。

### 8.5 反馈环路

「用户选的输入源」和「设备列表」耦合会形成环路：
切到耳机麦克风 → 蓝牙切 SCO → 设备列表变 → 判定「耳机没了」
→ 退回内置 → 蓝牙切回 A2DP → 再切 SCO……来回翻。
（这是上一个功能「选择输入源」的教训，那个功能最终因为
平台限制做不了，见 `TODO.md`。）

## 10. 用真实录音标定：F1 为什么整个丢了

> 这一节是**用真人录音 + Praat 对照**做出来的，不是合成信号。
> 结论推翻了之前所有基于合成信号的参数选择。

### 现象

真机上报 F1=1411、F2=2677（Praat 是 471 / 1540）。
看起来像「F1 检测不到」。

### 复现

拿真人录音（48 kHz）离线跑**和 App 完全一样**的流程：
FIR 降采样 → 预加重 → Hamming → 自相关 → Levinson → 求反转多项式根。

t=2.00s 那一帧：

```
App 的根（不加任何过滤）：
  [436(bw812), 1489(bw76), 2554(bw178), 3720(bw93), ...]

Praat：F1=470  F2=1453  F3=2493  F4=3650
```

**F1 的根一直都在 436 Hz**（Praat 470，误差 34 Hz）。
但它的**带宽是 812 Hz**，而代码里的带宽上限是 520 —— 被当「噪声峰」丢掉了。
于是 `roots[0]` 变成真正的 F2，后面全部**错位一格**。

界面上那个「F1=1411」其实就是 F2。

### F1 的带宽为什么这么大

不是 bug，是物理事实：真实声音里 F1 能量弱，又叠在声门源的强低频倾斜上，
LPC 只能用一个很宽的极点去拟合它。Praat 压根不做带宽过滤，所以没这个问题。

### 重新标定

用两段真人录音（各有 Praat 基准）扫描参数：

| 配置 | 真实录音误差 | 合成元音误差 |
|---|---|---|
| 原配置 pre=0.7, 带宽≤520 | **2156 Hz** | 187 |
| **pre=0.5, 带宽≤700** | **43 Hz** | **54** |
| pre=0.6, 带宽≤900 | 42 | 193（有元音崩） |

新配置在**两个基准上同时最好**，不是只对一段过拟合。

预加重也从 0.7 改成 0.5：0.7 是在合成信号上选的，
合成信号的声门源倾斜比真实声音「干净」，能承受更强的预加重；
真实声音里 0.7 会把 F1 的极点抹到 569 Hz、带宽 812，
更容易被过滤掉。阶数 16 保持 —— 那个标定是对的。

### 还没解决的：阶数敏感性

真人录音上发现，**LPC 阶数一变，F1 的根就时有时无**：

| 阶数 | 录音 A（Praat 420/1453） | 录音 B /u/（Praat 308/785） |
|---|---|---|
| 14 | F1 丢失（误差 2067） | F2=506（误差 308） |
| 16 | **F1=467 ✓（误差 110）** | F2=505 ✗ |
| 18 | F1 丢失（误差 2071） | **F2=731 ✓（误差 78）** |
| 20 | F1=933（误差 581） | F2=716（误差 89） |

没有任何单一阶数同时对两段都好。原因是 F1 的带宽正好压在过滤边界上，
阶数稍微一变就翻过去。

试过但**没用**的：
- 放宽带宽 + 按频带分配（阶数敏感性照旧）
- 包络找峰（F2 直接被跳过，误差 1200+）
- Burg 法（没有明显优势）
- 先高通滤掉低频隆隆声（照旧）

**要真正解决得换思路**：按 Praat 的做法在 LPC 频谱上找峰
（带频带约束的 hill-picking），而不是「求根 + 带宽过滤」。
记在 TODO 里。

### /u/ 的 F2 是已知弱项

`/u/` 的 F1 和 F2 靠得近（308 / 785，只差 2.5 倍），
LPC 容易把它们往中间拉。实测 F2 稳定落在 505–730（真值 785）。
测试里注明了这一点，容差给到 100 Hz。

**顺带一个反例**：之前拿 Peterson & Barney 的 /u/ 平均值（F2=870）
当基准，以为 App 报 783 是错的 —— 实际这段录音的 Praat 实测就是 785。
**个体差异比教科书平均值大得多**，这也是目标必须是一个「区域」而不是一个点的原因。


## 11. 最终结论：什么是能修好的，什么是方法本身的局限

用两段真人录音（各有 Praat 导出的共振峰轨迹）跑完整管线验证。

### 修好的

| 录音 | 修复前 | 修复后 | Praat |
|---|---|---|---|
| A（/e/ 类） | F1=1411 F2=2677（错位一格） | **F1=340 F2=1494** | F1=420 F2=1453 |
| B（/u/） | — | F1=278 F2=461 | F1=308 F2=785 |

录音 A 的误差从 **+1071/+1093** 降到 **−80/+41**。

关键改动就是两个数：预加重 0.7→0.5、带宽上限 520→700，
都是拿真实录音对照 Praat 标出来的（不是合成信号）。

### 修不好的，以及为什么

**1. F1 并进低频滚降的音，没有唯一"正确答案"**

录音 A 的 LPC 频谱包络从 150 Hz 起**单调下降**，
任何阶数、任何预加重下 1200 Hz 以下都**没有局部极大**：

```
pre=0.5 order=16:  150:0  300:-5  400:-9  600:-15  1000:-20  （一路降）
```

Praat 报的 F1=356 是它的模型在这条滚降上放的一个极点，
不是可分辨的共振峰。这种情况下 App 报 340（偏低 80）、
Praat 报 420，**两个都是模型的产物**，没有谁"对"。

**2. F1 和 F2 靠得近的音，阶数决定结果**

录音 B（/u/）的 F1=308、F2=785，只差 2.5 倍：

| 阶数 | 录音 A | 录音 B |
|---|---|---|
| 14 | F1 丢失 | F2=506 |
| **16** | **F1=467 ✓** | F2=505 ✗ |
| 18 | F1 丢失 | **F2=731 ✓** |
| 20 | F1=933 | F2=716 |

没有任何单一阶数同时对两段都好。

试过并且**都没解决**的：
- 放宽带宽 + 按频带分配
- 包络找峰（F2 被跳过）
- 倒谱平滑 + 找峰（伪峰太多）
- Burg 法（没有明显优势）
- 先高通 60–200 Hz
- 在 48 kHz 原始采样率上做（一样没 F1）
- Toeplitz 直接解方程（验证过 Levinson 实现无误，偏差 6e-12）

### App 现在怎么处理这种不确定

不是硬凑一个数字，而是**该说不确定的时候说不确定**：

1. `MAX_PLAUSIBLE_F1_HZ` —— F1 超过 1100 就报未知，不把 F2 当成 F1
2. `FormantTracker` —— 离群帧不跟着跳
3. `isF2Credible` —— F2 跟目标差太远（> 300 音分）就标「读数不稳」，
   目标区判定只用 F1
4. 5 帧中位数平滑 —— 显示值纹丝不动

录音 B 的 F2=461 相对目标 1018 差 1340 音分，会被标成「读数不稳」——
**不会照着错的值给用户训练建议**。

### 下一步（如果真的要做到 Praat 那个水平）

不是调参数能解决的，得换方法：

- [ ] **频谱 hill-picking**（Praat 的做法）：在 LPC 频谱上按频带找峰，
      而不是「求根 + 带宽过滤」。带宽完全不参与判定。
- [ ] **帧间跟踪**：用上一帧的 F1/F2 作为先验，抑制跳变和错位
- [ ] **共振峰校正**：用 F3 和频谱倾斜辅助判断圆唇/舌位，
      区分 F1/F2 靠得近的元音

## 10. 还没做的

- **共振峰轨迹**（LTCS）：把每帧的谱按时间累积画二维图，
  一眼看出共振峰怎么走
- **共振峰的帧间跟踪**：现在是每帧独立选峰，
  真实跟踪器会利用帧间连续性来抑制伪根
- **F3/F4**：16 kHz 分析域对 F3 偏高的人（女声）不够准，
  需要 48 kHz 另开一条支路
- **虚实检测**：见 `docs/voice-quality-detection.md`
  （那篇是更早的方案，LTAS 那条路还没实现）
