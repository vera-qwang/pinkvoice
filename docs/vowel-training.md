# 元音训练与音色分析 —— 设计与实现

> 状态：**已实现**（2026-11-19/20）。
> 讲的是「怎么做的」和「踩了哪些坑」。
> 功能层面的说明在 README。

---

## 1. 做了什么

App 现在有两个页面（底部标签切换）：

| 页面 | 回答的问题 |
|---|---|
| **监测** | 我现在多高？（原有的 f0 曲线） |
| **训练** | 我这个音**准不准、稳不稳**？ |

训练页三块内容：

1. **F1/F2 轨迹** —— 最近 8 秒的共振峰走势，和目标区（横带）的关系
2. **稳态度** —— 帧与帧之间的抖动
3. **音色轴** —— 薄虚 ↔ 厚实（需要个人基准）

### 为什么单独一页

不只是「主页面挤」：

- **数据不同**：监测画 f0 曲线，训练要 F1/F2 轨迹和音色轴
- **交互不同**：监测是「打开就看」，训练是「选目标 → 练 → 看反馈」，
  需要参照物
- **性能**：LPC 分析只在训练页跑，监测页照旧轻量

## 2. 整体流程

```
麦克风 ─48kHz─► FIR 降采样 ─16kHz─┬─► YIN ──► f0 曲线（监测页）
                                  │
                                  └─► LPC ──► 共振峰 ─┬─► F1/F2 轨迹
                                                       ├─► 元音识别
                                                       ├─► 稳态度
                                                       └─► 音色轴
```

**两条支路共用同一份 16 kHz 数据**，各自维护滑动窗口
（窗口 1024 = 64 ms，跳帧 256 = 16 ms），所以时间对齐，
界面上的读数能直接叠着看。

LPC 分析**默认不开** —— 监测页不需要，只在训练页启用。

## 3. LPC 求共振峰

### 3.1 为什么用求根，不是在包络上挑峰

周期声源的梳状结构会让包络上出现一堆几乎等高的起伏。
实测 `/a/` 的 F2 就是个只有零点几 dB 的小凸起 —— 按「最高峰」选会
直接跳过它选到 F3。

求根没有这个问题：每个根就是一个独立的共振候选。

### 3.2 求的是**反转多项式**

LPC 多项式 `A(z) = 1 + a₁z⁻¹ + … + aₚz⁻ᵖ`，令 `w = z⁻¹`，
它的根在**单位圆外**（稳定极点的倒数的倒数），
数值条件很差 —— Durand-Kerner 的初值在圆上、根在圆外，
经常收敛不了。真机上表现为大部分帧一个根都求不出来。

反转多项式 `q(w) = wᵖ + a₁wᵖ⁻¹ + … + aₚ` 的根**就是极点本身**
（`|z| < 1`，在单位圆内），条件好得多。

### 3.3 参数**不是标定出来的，是读源码读出来的**

> 这一节整段重写过。原来是用合成元音扫参数扫出来的
> （预加重 0–0.97 × 阶数 12–20 × 两种提取方法），
> 结论**全错** —— 因为合成元音太干净，而复刻的 LPC 本身有 bug。

正确做法是**读 Praat 源码**，然后拿真 Praat 验证：

| 参数 | Praat 源码 | 之前的实现 | 现在 |
|---|---|---|---|
| 分析速率 | `Sound_resample(me, maximumFrequency*2, 50)` → **11 kHz** | 12 kHz（猜的） | **11 kHz** |
| 阶数 | `2 × nFormants` = **10** | 11（扫出来的） | **10** |
| 窗 | **高斯窗** `exp(-48(i-imid)²/(n+1)²)` | Hamming | **高斯窗** |
| 预加重 | `exp(-2π·f0·dx)`，**dx 是重采样后的** | 按原始采样率算（错） | 按分析速率算 |
| 带宽上限 | **没有**（只挡退化极点） | 520 Hz | **去掉** |

Praat 的完整配置在 `fon/Sound_to_Formant.cpp` 和 `fon/Sound.cpp` 里，
参数就写在那几行里。

### 3.4 分析速率是最容易被忽略的一个

极点频率 = 辐角 × fs / 2π，所以**速率差一点点，结果就差几十 Hz**。
同一条录音，只改分析速率和阶数：

| 分析速率 | 阶数 | 与真 Praat 的平均误差 |
|---|---|---|
| 10 kHz | 10 | 200 Hz |
| **11 kHz** | **10** | **23 Hz** |
| 12 kHz | 10 | 471 Hz（/o/ 的 F1+F2 合并，F2 报成 F3） |
| 12 kHz | 11 | 32 Hz |
| 16 kHz | 10–12 | 1218 Hz（完全不可用） |

**只有 11 kHz + 10 阶在五个元音上全对。**

### 3.5 阶数敏感到什么程度

同一条录音（用户的「啊」），只改阶数：

| 阶数 | F1 | F2 | σ(F1) |
|---|---|---|---|
| 8 | 456 | 1545 | 133 |
| **10** | **417** | **1472** | **43** |
| 11 | 451 | 1488 | 195 |
| 12 | 642 | 1492 | 236 |
| 13 | 826 | 1507 | 77 |

10 阶和真 Praat 的 419/1453 **只差 2 Hz**，σ 只有 43 Hz；
11 阶差 32 Hz，σ 是 195（差 4.5 倍），而且一阶之差就崩。

12 阶以上 F1 会跑到 640–850 —— 多出来的极点把 F1「吸」走了。

### 3.6 两道过滤，一个坑

**稳定性**：LPC 拟合出的中间共振峰有时会落到单位圆外一点点。
一刀切丢掉的话 F2 经常整个消失。放宽到 `|z| ≤ 1.05`。

**带宽**：**不要用带宽上限挑共振峰。**

以前卡 520 Hz，是因为真信号里共振峰被手机麦和房间混响抹宽，
实测 `/a/` 的 F2 根带宽 484–510 Hz —— 于是 `/a/` 的 F1（带宽 812–900 Hz）
被当成了「伪根」丢掉，整个错位一格。

Praat 不用带宽做筛选，**只挡退化极点**（带宽为 0 或负）。
现在也这么做。带宽这信息不是没用，是**不能拿它当筛子**。

## 4. 元音识别

### 4.1 归一化：折算到标准声道长度

绝对共振峰频率因人而异 —— 声道长的人所有共振峰都低。
语音学的标准做法是折算到 17.5 cm 的标准男性声道，
这样所有人的元音图在同一个坐标系里。

**声道长度怎么估**：不要求用户知道，而是用录基准时念 `/a/` 的
实测 F1 反推 —— F1 测出来低 = 声道长。

> 这个公式的方向一开始写反了（`normalized / measured`），
> 被单元测试抓到的。

### 4.2 距离度量

```
距离 = sqrt(ΔF2² + (1.4·ΔF1)²)
```

F2 的权重 1.4 倍 —— 舌位变化比开口度更容易被听出来。

「认得出」的阈值：180（归一化 Hz）。

## 5. 稳态度

测的是**帧与帧之间的抖动**，单位换算成**音分**（和听感一致）。

两个坑，都被单元测试抓到了：

- **音分差要取绝对值**。抖动是双向的，不取绝对值的话正负差值
  互相抵消，中位数 ≈ 0，看起来比实际稳得多。
- **F1/F2 的抖动取平均，不取 min**。取 min 的话只要有一个维度稳
  就完全掩盖了另一个维度的抖动 —— 实测抖动 ±60 Hz 的信号会拿满分。

映射：抖动 ≤ 10 音分 → 1.0（几乎不动）；≥ 120 音分 → 0.0。

## 6. 音色轴

把「虚实 / 前共振 / 后共振 / 厚薄」合成**一条轴**（−1..+1）。

这些词在频谱上是高度相关的，分开做几个指标用户会看到互相
矛盾的数字。

两个子特征，各自相对**个人基准**标准化后加权：

```
轴位置 = 0.6 × z(谱倾斜) + 0.4 × z(F1)
```

### 为什么必须用个人基准

「厚」没有绝对标准：男声天生低频多、喉腔大小不同、
麦克风频响 + 蓝牙染色也不同。任何固定阈值都是错的。

做法：录一段 `/a/` 作为基准，之后显示「比你的基准偏亮还是偏暗」。

## 7. 真机验证

用**合成的已知元音**（`tools/gen_vowel.py`：Rosenberg 声门源 +
三段共振器）经 Mac 喇叭播放、手机麦采集：

| 元音 | 期望 F1/F2 | 实测（Note 20 Ultra） | 识别 |
|---|---|---|---|
| /a/ | 730 / 1090 | 724 / 1401 | 「啊」✓ |
| /i/ | 270 / 2290 | 210 / 2375 | 「衣」✓ |
| /u/ | 300 / 870 | 257 / 810 | 「乌」✓ |

`/a/` 的 F2 差 311 Hz 是**测试链路的声学限制**：
笔记本喇叭 → 房间 → 手机麦这条路上，1100–1300 Hz 的包络只差 2 dB，
峰位本就模糊。干净合成信号上同一配置是 723/1060（误差 7/30 Hz）。

**这说明真机上的精度下限由采集链路决定，不是算法。**

## 8. 真机验证：一次**结论完全错了**的排查

> 这一节记录的是一次自我纠错 —— 结论是错的，
> 而且错的方向很典型，值得留着。

### 当时的结论

在 Note 20 Ultra 上用「Mac 喇叭 → 房间 → 手机麦」测，
`/a/`（期望 F1=730 F2=1090）报成 **F1 724 / F2 2407**。

当时的判断是：

> F2 偶尔会整个消失（共振峰被噪声淹没），
> 按频率取第二个根拿到的其实是 F3。
> 笔记本喇叭放不出 300 Hz 的共振峰，
> 到达麦克风的信号里这些共振峰已经不存在了。
> **算法在这种情况下报出的是「信号里实际有的东西」，不是它算错了。**

为了"证明"这个结论，还写了个单元测试：
拿干净的合成 /u/ 加上低频滚降和噪声，
看 F1 会不会偏离 —— 确实偏离了（310 → 387）。

于是又花了好几轮去改算法：
包络判据、频带分配法、伪根过滤……全都试过、都失败了。

### 真相：是**测试信号**不真实

有人提了个问题：

> 「有没有可能是 F2 检测是对的，你的标定错了？」

这才去**独立**验证 —— 不走 App 的代码，用纯 Python 的 Goertzel
直接分析合成的 WAV：

```
720 Hz    0.0 dB     ← F1
1080 Hz  -26.2 dB    ← F2
```

**合成的 F2 比 F1 低 26 dB。** 真实的元音不是这样 ——
三个共振峰的高度是接近的（F1 最强，F2 低 5–15 dB，F3 再低一点）。

不真实的信号经过喇叭和房间之后，F2 直接掉进噪声底，
LPC 拟合噪声、在 F3 附近产生一个伪根 —— **信号的问题，不是算法的问题。**

### 修好之后

在级联之后加一道**峰值均衡**（把三个共振峰拉到真实比例）：

| | F2 相对 F1 | /a/ 实测 F1/F2 | 误差 |
|---|---|---|---|
| 修之前 | **−26 dB** | 724 / 2407 | F2 差 1300 Hz ✗ |
| 修之后 | **−8 dB** | **735 / 1159** | **F2 差 69 Hz ✓** |

F2 的误差从 1300 Hz 降到 69 Hz。**算法一直是对的。**

### 为什么级联会这样

朴素的「声门源 → 级联三个共振器」里，
第二个共振器吃的是**第一个共振器整形之后**的信号，
而第一个（F1=730, BW=60）的裙边在 1090 Hz 处压了约 15 dB。

真实声道的共振峰峰值增益取决于该处的反射和损耗，
不是级联里"前一级把后一级喂弱了"那么简单。
所以修法不是调带宽（试过，没用），而是**级联完做一次 EQ**。

### 教训

**验证工具本身要先被验证。**

之前所有的单元测试都是「合成信号 → 分析 → 对比参考值」，
看起来是自洽的，但**信号和参考值来自同一张表**，
所以测的其实是"实现和合成器一致"，不是"符合真实人声"。

现在加了三条防线：

1. `tools/gen_vowel.py --check` —— 独立测量输出频谱，打印三个峰的相对电平
2. `VowelSynth`（测试用的共享合成器）—— 同样做峰值均衡
3. `syntheticSpectrumLooksLikeRealVoice` 测试 —— 守住「峰之间不能差 15 dB 以上」

第 3 条是关键：**它守的是测试信号本身**。
以后谁改了合成器，这条测试会立刻发现。

### 剩下的真实限制

`/u/`（F1=300, F2=870）在这条测试链路上**仍然测不准** ——
因为 300 Hz 和 870 Hz 在笔记本喇叭的响应里太弱。

验证：把同样的 /u/ 抬到 500/1150/2500，立刻测得
**F1 374 / F2 1092**（误差 58 Hz），识别「乌」✓

所以这条链路的**频率下限**大概在 400–500 Hz。
真机使用时手机在嘴边，信噪比高得多，不受这个限制。

## 9. 这一页到底该干什么（重要设计决定）

### 9.0 从「元音图」改成「F1/F2 轨迹」

> 这一节整段重写过。原来这一页画的是**元音图**
> （F1-F2 散点 + 六个目标区域云）。

**为什么改。** 那个设计有几个实际问题：

1. **看不出稳不稳。** 训练要练的就是「保持」——
   散点图上只有一个点，稳不稳全靠盯着数字猜。
   轨迹是一条线，平不平一眼就看出来。
2. **六个目标区域叠在一起是浆糊。** 每个元音一个椭圆，
   在窄屏上互相重叠，没法判断自己在哪个区域里。
   改成「每个轴一条横带」就清楚多了。
3. **引入了错误的因果。** 一个点 + 一个黑点，
   很容易读成「落在点上 = 练好了」——
   而目标区本来就是一片分布，不是一个点。
4. **和 F0 页的交互模型不一致。** 那边是「横轴 = 时间」的曲线，
   这边是散点，用户要学两套读图方式。

**新设计**：上下两条带（F1 上、F2 下），横轴都是时间。

- **横向的阴影带** = 当前目标元音的目标区（±120 音分）
- **曲线** = 最近 8 秒的 F1/F2
- **右端圆点** = 当前值（进带内变绿）

**纵轴用对数刻度**，而且两个轴的跨度一样宽（都是 2.6 个八度）——
这样目标带在两条带上**一样高**，用户可以直接用眼睛比
「我离带子还差多少」，不用在脑子里换算 Hz。

代价：没有元音图的「绝对位置」视角了，也没了空间上的元音身份。
但身份那一行文字还在，而且**空间上的位置本来就是问题所在** ——
六个椭圆叠在一起的那个图，正是让人误读的地方。

顺带删掉了 `VowelChart.kt`（没人用了）和导航栏上那个
「方框 + 三个点」的图标（改成轨迹的样子）。



> 这一节记录的是**目标本身**的重新定义 ——
> 之前把这一页做成了「元音识别器」，方向就错了。

### 之前做错了什么

原设计：图上画几个标准元音的黑点，用户选一个目标，
把自己的点移到那个点上就算练好了。

**两个都错**：

1. **元音图本身的用途是区分元音身份**（舌位前后高低），
   不是衡量女性化程度。
2. 女性化的目标**不是**「把 /a/ 念成标准 /a/」。

### 真正的目标

> **在保持元音可辨认的前提下，整体把共振峰空间往前、往上抬**
> （等效更短声道、更靠前共鸣），
> 同时搭配合适 F0、稳定发声、语调、嗓音质量。

这是一句关于**空间位移**的话，不是关于某个点的。

所以目标应该长这样：

- **目标是一个区域，不是一个点** ——
  真实说话人的共振峰散布很宽，女性元音是一片分布，
  落在区域里就算达标
- **元音身份和女性化目标是分开的两件事** ——
  界面上必须分成两行，不能混在一起
- **给出的是「往哪调」，不是「你错了」** ——
  「F2 偏低 → 舌位再往前一点」，比一个笼统的距离有用得多

### 现在的设计

```
目标：把共振峰空间往前、往上抬，同时保持元音可辨认

[图表：每个元音一片目标区域云，当前目标高亮 + 当前位置]

发「啊」，把点移进目标区                    目标 F1 803 / F2 1308
元音身份                              你在发「啊」
F1 偏低 88                          F2 ✓ 达标
共振峰前移   F1 -2%  F2 14%   （目标 +10% / +20%）
再调一点：嘴再张开一些
[保持进度条]  已保持 2.3 秒 / 目标 10 秒
```

**目标值怎么来的**：从吴宗济的**普通话**元音位置出发，
按**逐元音**的男→女比值换算（往上抬 F1、往前移 F2）。
比值因元音而异 —— 衣的 F1 只抬 1.129 倍（舌位已经到顶），
而啊的 F1 抬 1.299 倍（开口度可以大幅收小）。详见 §16。

**目标区域多大**：**±120 音分**（每个元音的 ±7.18%）。
用音分而不是绝对 Hz —— 频率是等比关系，
用 Hz 定容差的话不同元音难度天差地别（衣的 F1=310 只能容忍 ±22 Hz，
而哦的 F2=850 能容忍 ±61 Hz，差三倍）。
用音分每个元音都是 ±12%，**练哪个都一样难**。

> 之前这里是绝对值（±80/±180 Hz），后来改成音分。
> 又验证过：实测噪声只有 F1 σ 6 Hz / F2 σ 21 Hz（§15），
> ±120 音分是它的 3 倍，**够用**，不用再放宽。

### 归一化不再显示

之前页面顶上写「声道 17.5 cm（折算到…）」。

**归一换算是跨人对比的科研工具，不是初学者训练目标** ——
用户看不懂这个换算，也不知道该拿它怎么办。
它是背后的计算细节，不该出现在训练界面里。

现在界面上只说人话：「把共振峰空间往前、往上抬」。

### 已知限制：身份和女性化是纠缠的

识别用的是**自然位置**的元音坐标，而女性化目标在它前面 ——
声音往前挪之后，识别标签会跟着漂。

处理办法：每个元音有**两个参考点**（自然位置 + 女性化目标位置），
识别时两个都参与，但目标点要额外付 90 Hz 的代价。
这样在目标位置能认对（6/6），自然位置上的识别一点没变差。
细节和实测数据见 §16。

**根因是元音图本身的局限**：/啊/ 和 /哦/ 的区别主要在圆唇
（影响 F3 和频谱倾斜），不在 F1/F2 上。
只靠 F1/F2 分不出这两个 —— 这是元音图的天花板。

要彻底解决得引入别的信号：F3、频谱倾斜、或者 F0。
记在 TODO 里。

## 10. 踩过的坑

### 8.1 预加重和阶数要一起标定

单独看任何一个都不够 —— 阶数 12 在合成信号上最好，
但真机上会丢 F2；预加重 0.97 在合成信号上会把 `/i/` 的 F1 压没。

### 8.2 测试信号要用声门流的**导数**

唇端辐射是 +6 dB/oct。拿声门流本身（频谱 −12 dB/oct）去级联的话，
`r[1]/r[0]` 会接近 1，Levinson 的反射系数直接爆掉，
递推发散、系数变成回文结构 —— 看起来像 LPC 写错了，其实是信号造错了。

### 8.3 反射系数必须钳位

`|m| < 1` 否则预测误差 `e` 变号，后面所有系数全错。
真机上遇到静音帧、突发噪声就会这样。

### 8.4 合成元音的频谱比例（最贵的一个坑）

**信号不真实 → 验证结论完全错 → 照着错结论改算法。**

详见第 8 节。教训是：**验证工具本身要先被验证**，
而且要独立验证（不走被测代码）。

### 8.5 反馈环路

「用户选的输入源」和「设备列表」耦合会形成环路：
切到耳机麦克风 → 蓝牙切 SCO → 设备列表变 → 判定「耳机没了」
→ 退回内置 → 蓝牙切回 A2DP → 再切 SCO……来回翻。
（这是上一个功能「选择输入源」的教训，那个功能最终因为
平台限制做不了，见 `TODO.md`。）

## 11. 用真实录音标定：F1 为什么整个丢了

> 这一节是**用真人录音 + Praat 对照**做出来的，不是合成信号。
> 结论推翻了之前所有基于合成信号的参数选择。

### 现象

真机上报 F1=1411、F2=2677（Praat 是 471 / 1540）。
看起来像「F1 检测不到」。

### 复现

拿真人录音（48 kHz）离线跑**和 App 完全一样**的流程：
FIR 降采样 → 预加重 → Hamming → 自相关 → Levinson → 求反转多项式根。

t=2.00s 那一帧：

```
App 的根（不加任何过滤）：
  [436(bw812), 1489(bw76), 2554(bw178), 3720(bw93), ...]

Praat：F1=470  F2=1453  F3=2493  F4=3650
```

**F1 的根一直都在 436 Hz**（Praat 470，误差 34 Hz）。
但它的**带宽是 812 Hz**，而代码里的带宽上限是 520 —— 被当「噪声峰」丢掉了。
于是 `roots[0]` 变成真正的 F2，后面全部**错位一格**。

界面上那个「F1=1411」其实就是 F2。

### F1 的带宽为什么这么大

不是 bug，是物理事实：真实声音里 F1 能量弱，又叠在声门源的强低频倾斜上，
LPC 只能用一个很宽的极点去拟合它。Praat 压根不做带宽过滤，所以没这个问题。

### 重新标定

用两段真人录音（各有 Praat 基准）扫描参数：

| 配置 | 真实录音误差 | 合成元音误差 |
|---|---|---|
| 原配置 pre=0.7, 带宽≤520 | **2156 Hz** | 187 |
| **pre=0.5, 带宽≤700** | **43 Hz** | **54** |
| pre=0.6, 带宽≤900 | 42 | 193（有元音崩） |

新配置在**两个基准上同时最好**，不是只对一段过拟合。

预加重也从 0.7 改成 0.5：0.7 是在合成信号上选的，
合成信号的声门源倾斜比真实声音「干净」，能承受更强的预加重；
真实声音里 0.7 会把 F1 的极点抹到 569 Hz、带宽 812，
更容易被过滤掉。阶数 16 保持 —— 那个标定是对的。

### 还没解决的：阶数敏感性

真人录音上发现，**LPC 阶数一变，F1 的根就时有时无**：

| 阶数 | 录音 A（Praat 420/1453） | 录音 B /u/（Praat 308/785） |
|---|---|---|
| 14 | F1 丢失（误差 2067） | F2=506（误差 308） |
| 16 | **F1=467 ✓（误差 110）** | F2=505 ✗ |
| 18 | F1 丢失（误差 2071） | **F2=731 ✓（误差 78）** |
| 20 | F1=933（误差 581） | F2=716（误差 89） |

没有任何单一阶数同时对两段都好。原因是 F1 的带宽正好压在过滤边界上，
阶数稍微一变就翻过去。

试过但**没用**的：
- 放宽带宽 + 按频带分配（阶数敏感性照旧）
- 包络找峰（F2 直接被跳过，误差 1200+）
- Burg 法（没有明显优势）
- 先高通滤掉低频隆隆声（照旧）

**要真正解决得换思路**：按 Praat 的做法在 LPC 频谱上找峰
（带频带约束的 hill-picking），而不是「求根 + 带宽过滤」。
记在 TODO 里。

### /u/ 的 F2 是已知弱项

`/u/` 的 F1 和 F2 靠得近（308 / 785，只差 2.5 倍），
LPC 容易把它们往中间拉。实测 F2 稳定落在 505–730（真值 785）。
测试里注明了这一点，容差给到 100 Hz。

**顺带一个反例**：之前拿 Peterson & Barney 的 /u/ 平均值（F2=870）
当基准，以为 App 报 783 是错的 —— 实际这段录音的 Praat 实测就是 785。
**个体差异比教科书平均值大得多**，这也是目标必须是一个「区域」而不是一个点的原因。


## 12. 最终结论：什么是能修好的，什么是方法本身的局限

用两段真人录音（各有 Praat 导出的共振峰轨迹）跑完整管线验证。

### 修好的

| 录音 | 修复前 | 修复后 | Praat |
|---|---|---|---|
| A（/e/ 类） | F1=1411 F2=2677（错位一格） | **F1=340 F2=1494** | F1=420 F2=1453 |
| B（/u/） | — | F1=278 F2=461 | F1=308 F2=785 |

录音 A 的误差从 **+1071/+1093** 降到 **−80/+41**。

关键改动就是两个数：预加重 0.7→0.5、带宽上限 520→700，
都是拿真实录音对照 Praat 标出来的（不是合成信号）。

### 修不好的，以及为什么

**1. F1 并进低频滚降的音，没有唯一"正确答案"**

录音 A 的 LPC 频谱包络从 150 Hz 起**单调下降**，
任何阶数、任何预加重下 1200 Hz 以下都**没有局部极大**：

```
pre=0.5 order=16:  150:0  300:-5  400:-9  600:-15  1000:-20  （一路降）
```

Praat 报的 F1=356 是它的模型在这条滚降上放的一个极点，
不是可分辨的共振峰。这种情况下 App 报 340（偏低 80）、
Praat 报 420，**两个都是模型的产物**，没有谁"对"。

**2. F1 和 F2 靠得近的音，阶数决定结果**

录音 B（/u/）的 F1=308、F2=785，只差 2.5 倍：

| 阶数 | 录音 A | 录音 B |
|---|---|---|
| 14 | F1 丢失 | F2=506 |
| **16** | **F1=467 ✓** | F2=505 ✗ |
| 18 | F1 丢失 | **F2=731 ✓** |
| 20 | F1=933 | F2=716 |

没有任何单一阶数同时对两段都好。

试过并且**都没解决**的：
- 放宽带宽 + 按频带分配
- 包络找峰（F2 被跳过）
- 倒谱平滑 + 找峰（伪峰太多）
- Burg 法（没有明显优势）
- 先高通 60–200 Hz
- 在 48 kHz 原始采样率上做（一样没 F1）
- Toeplitz 直接解方程（验证过 Levinson 实现无误，偏差 6e-12）

### App 现在怎么处理这种不确定

不是硬凑一个数字，而是**该说不确定的时候说不确定**：

1. `MAX_PLAUSIBLE_F1_HZ` —— F1 超过 1100 就报未知，不把 F2 当成 F1
2. `FormantTracker` —— 离群帧不跟着跳
3. `isF2Credible` —— F2 跟目标差太远（> 300 音分）就标「读数不稳」，
   目标区判定只用 F1
4. 5 帧中位数平滑 —— 显示值纹丝不动

录音 B 的 F2=461 相对目标 1018 差 1340 音分，会被标成「读数不稳」——
**不会照着错的值给用户训练建议**。

### 下一步（如果真的要做到 Praat 那个水平）

不是调参数能解决的，得换方法：

- [ ] **频谱 hill-picking**（Praat 的做法）：在 LPC 频谱上按频带找峰，
      而不是「求根 + 带宽过滤」。带宽完全不参与判定。
- [ ] **帧间跟踪**：用上一帧的 F1/F2 作为先验，抑制跳变和错位
- [ ] **共振峰校正**：用 F3 和频谱倾斜辅助判断圆唇/舌位，
      区分 F1/F2 靠得近的元音


## 13. 换方法：从 Praat 反推出配置

上一节说「要真正解决得换 Praat 的频谱找峰思路」。
实际做下来发现**不用换思路**，是**配置全错了**。

### 怎么找到正确配置的

拿真人录音在 **48 kHz 原始采样率**上反复试，
把 Praat 导出的 F1–F4 轨迹当中位数基准，穷举：

- 分析采样率：8k / 10k / 11.025k / 12k / 12.8k / 16k / 48k
- LPC 求法：自相关 + Levinson vs **Burg**
- 阶数：8–24
- 窗长：25–75 ms
- 预加重：0 / 50 Hz / 100 Hz 起点

### 结果：五个参数全错了

| 参数 | 原来 | 正确 | 差在哪 |
|---|---|---|---|
| 分析采样率 | 16 kHz | **12 kHz** | Praat 会重采样到「2 × 共振峰上限」（5 kHz → 10 kHz） |
| 求法 | 自相关 + Levinson | **Burg** | Praat 用的就是 Burg，对短数据、共振峰靠近时更稳 |
| 阶数 | 16 | **11** | 见下 |
| 窗长 | 64 ms | **50 ms** | 差别不大，50 ms 略稳 |
| 预加重 | 固定系数 0.7 | **从 50 Hz 起** | Praat 的默认值，温和得多（1 kHz 处只衰减 6 dB） |
| 带宽过滤 | ≤ 520 Hz | **不做** | Praat 压根不按带宽选峰 |

### 阶数为什么是 10 而不是 11

Praat 的公式直接给了答案：`2 × nFormants` = 2 × 5 = **10**。

而 11 阶是**扫出来的**「最优」—— 那次扫描用的复刻有 bug，结论不可信。
换到真值之后，同一条录音（用户的「啊」）上：

| 阶数 | F1 | F2 | σ(F1) |
|---|---|---|---|
| 8 | 456 | 1545 | 133 |
| **10** | **417** | **1472** | **43** |
| 11 | 451 | 1488 | 195 |
| 12 | 642 | 1492 | 236 |
| 13 | 826 | 1507 | 77 |

**这个敏感性是方法本身的弱点**，不是调参能消除的。
App 靠 `isF2Credible` 在 F2 明显不对时标「读数不稳」，而不是给错的值。

### 最终精度（五段真人录音，对照真 Praat）

| 元音 | App F1/F2 | Praat F1/F2 | 误差 |
|---|---|---|---|
| 啊 | 412 / 1463 | 420 / 1453 | **19 Hz** |
| 鹅 | 385 / 1270 | 396 / 1266 | **14 Hz** |
| 衣 | 284 / 2297 | 282 / 2304 | **8 Hz** |
| 哦 | 484 / 787 | 500 / 753 | **49 Hz** |
| 乌 | 306 / 791 | 308 / 785 | **8 Hz** |

平均 **20 Hz**。修复前是 2156 Hz（错位一格）。


### 实现上的两个坑

**1. Burg 的后向误差下标差一**

第一版写成了 `b[i] += k·f[i-1]`，正确是 `b[i-1] += k·f[i]`。
症状：反射系数从 k2 起全部不对，极点偏移几百 Hz。
发现方式：把重采样后的样本导出，用 Python 参考实现对**同一份数据**跑，
逐项比对反射系数 —— 一眼看出 k1 对、k2 起错。

**2. 重采样器开头的历史不足**

多相滤波器需要 `lookback` 个历史样本，开头没有的话
「历史不够 → break」会永远成立，一个样本都产不出来。
修法：起始偏移设成 `-lookback`，前面补零当历史。

### 测试策略也跟着改了

之前用合成信号断言「/a/ 应该出 730/1090」，**全绿，但真机全错**。
合成信号缺了声门源倾斜、房间、麦克风，和真实语音差太远 ——
拿它标定参数会被误导。

现在：
- **精度**由 `RealRecordingFormantTest` 用真人录音 + Praat 基准守（五段，平均 32 Hz）。
  音频含个人声音，不进仓库；本地放了就跑，没有就跳过。
- **合成信号**只做结构性断言（有序、F1 在范围内、确定性、静音拒绝）。
- **重采样器**单独测（频率不变、幅度不变、直流增益、分块一致）。


## 14. F1/F2「乱飘」的两个真凶

用户反复反馈「监听的时候 F1/F2 还是在乱跳」。查下来是两个独立问题叠加。

### 真凶一：噪音帧也被当成元音分析

以前 `quality?.process(floatsAnalysis, m)` **无条件对每一帧跑 LPC**，
完全不管这一帧是语音还是环境噪音。

在用户录音的**静音段**（纯环境噪音）跑分析，得到：

```
噪音 → 297/1611   455/1318   399/1300   385/1515
噪音 → 936/2136   400/1384   474/1342   394/1413
```

**全是看起来很像元音的值。** 也就是说用户没说话时，
界面照样显示「F1=400 F2=1400」—— 那当然是在乱跳。

#### 修法：用 YIN 的判定做门控

好在 YIN 本来就在同一份数据上跑，而且分得非常干净。
实测五段真人录音：

| | clarity 中位 | p10 | p90 |
|---|---|---|---|
| 语音段 | 0.73–0.85 | ≥ 0.58 | 0.82–0.94 |
| 环境噪音 | **0.00** | 0.00 | **0.00** |

噪音里 YIN 直接报 `hz = 0`（找不到周期）。
所以门控几乎白拿：`voiced = hz > 0 && clarity >= 0.5`。

再加一层**起音确认**（连续 2 帧才算，和 `PitchTracker.onsetFrames` 同思路），
挡掉噪音里 YIN 的孤立误判。

实测效果：

| 录音 | 噪音段有输出的帧 |
|---|---|
| A | 0 / 57 |
| E | 0 / 50 |
| I | 4 / 59 |
| O | 1 / 52 |
| U | 2 / 87 |

语音段的输出帧数完全不变（251/210/187/202/206）—— 不误伤正常说话。

### 真凶二：平滑链路几乎透明

| 元音 | 原始 σ(F1) | 修复前显示 σ | 修复前跳动 |
|---|---|---|---|
| A | 63 | 61 | 10% |

两个原因：
1. **跟踪器的「接近」分支直接透传原始值**（`acceptRatio = 0.20`
   意味着 ±80 Hz 的漂移原样放行）
2. **任何一帧无效就 `reset()`** —— 一个坏帧把跟踪器状态和
   5 帧中位数历史全扔掉，下一帧从头开始

修法：中位数窗口 5 帧 → **17 帧（272 ms）**，坏帧补洞不再清空。

| 窗口 | 延迟 | A | E | I | O | U |
|---|---|---|---|---|---|---|
| 5 | 80 ms | 7% | 0 | 0 | 0 | 0 |
| 13 | 208 ms | 2% | 0 | 0 | 0 | 0 |
| **17** | **272 ms** | **0%** | 0 | 0 | 0 | 0 |

中位数偏差几乎不变（−28 ~ +5 Hz）——**精度没为稳定牺牲**。
272 ms 对「保持元音 1–3 秒看是否到位」的训练场景可以接受。

### 为什么 A 的 F1 天生就飘

逐帧看极点：**F2/F3 非常稳**（1419–1505 / 2500–2580），
但 F1 在 **234–495** 之间游走。这不是噪声 —— 是这个音的
F1 极点位置本身模糊（它并进了低频滚降，LPC 包络在 1200 Hz
以下没有局部极大）。中位数是对的（386，Praat 420），
但逐帧值必然乱跳。**这种情况只能靠时间窗压平。**

### 回归测试

- `VoicingGateTest` —— 真人录音的噪音段不该有输出
- `RealRecordingFormantTest.displayedValuesAreStable` ——
  显示值跳动率超过 5% 就失败

## 15. 测量噪声：到底有多少

用户要求「先解决测量噪声的问题」。查下来发现，
**之前关于噪声的所有判断都是错的** —— 测法本身有问题。

### 错在哪

**第一，离线复刻管线漏了 YIN 门控。**
App 里 YIN 先判断这一帧是不是语音，不是语音就根本不跑 LPC。
测噪声用的管线没有这一步，于是把**静音段也当语音分析了**。

实测 YIN 的 clarity 分布是**双峰**的 —— 要么 0（17–27% 的帧），
要么 ≥0.8（71–81%），中间几乎没有。所以 YIN 门控一个就够，
**不需要**再加能量门控。

**第二，把起音过渡算进了「抖动」。**
共振峰的大幅变化来自**元音的起音过渡**，是生理事实，不是噪声：

| 元音 | 起音时 | 稳定段 |
|---|---|---|
| 衣 | F1 474→283，F2 **1522→2260** | F1 278，F2 2260 |
| 乌 | F1 232→307，F2 **1656→807** | F1 303，F2 763 |

人从一个音滑进另一个音（或者从静音滑进来），共振峰会连续变化 ——
显示出来也是对的，不该算进「发声稳不稳」。

### 真实数字

走 App 完整链路（YIN 判定喂给分析器当门控），
量语音段**中间 0.77 秒**（避开起音/收音过渡）：

| 元音 | F1 σ | F2 σ | (P90-P10) |
|---|---|---|---|
| 啊 | 15 | 9 | 35 / 6 |
| 鹅 | 3 | 13 | 7 / 29 |
| 衣 | 3 | 13 | 3 / 32 |
| 哦 | 5 | 30 | 12 / 68 |
| 乌 | 3 | 41 | 4 / 80 |

**平均 F1 σ ≈ 6 Hz，F2 σ ≈ 21 Hz。**

### 结论：目标区半径不用改

之前担心「目标区 ±62 Hz < 噪声 σ 88 Hz，数学上到不了位」。
实测噪声只有 21 Hz，目标区是它的 3 倍 —— **够用**。
不用为了迁就一个错误的噪声估计去放大目标区。

> 教训：先确认**测的是不是要测的东西**，再去改被测对象。
> 这次如果直接照着「σ 88 Hz」去加滤波器，
> 会在一个不存在的问题上花很多功夫。

## 16. 目标区可达性：比噪声严重得多的问题

查噪声的时候顺带发现一个更大的问题。

### 现象

目标区锚在「人口平均值」上（吴宗济男性值 × 男女比值）。
但**每个人和人口平均值都有差距**，差距可以很大。

用户自己五段录音的实测值 vs 吴宗济的普通话男性值：

| 元音 | 用户实测 | 吴宗济男性 | F1 差 | F2 差 |
|---|---|---|---|---|
| 啊 | 419 / 1454 | 770 / 1100 | **−351（−46%）** | +354（+32%） |
| 鹅 | 400 / 1278 | 550 / 1100 | −150 | +178 |
| 衣 | 288 / 2285 | 310 / 2100 | −22 | +185 |
| 哦 | 493 / 773 | 550 / 850 | −57 | −77 |
| 乌 | 311 / 826 | 400 / — | −89 | — |

**平均 F1 低 22.6%，F2 高 12.0%** —— 也就是说，
用户天生就在「声道更短、更靠前」的方向，**已经偏女性化**。

用人口平均值当目标，等于要求用户「变成平均女性」，而不是「比现在更女性」。
结果每个元音都够不到：

| 元音 | 实测 F1 | 目标区 F1 | 差 |
|---|---|---|---|
| 啊 | 419 | 861 ± 62 | **−442**（半径的 7 倍） |
| 鹅 | 400 | 779 ± 56 | −379 |
| 衣 | 288 | 319 ± 23 | −31（F2 −394） |
| 哦 | 493 | 673 ± 48 | −180 |
| 乌 | 311 | 354 ± 25 | −43（F2 −192） |

### 两个可能的解法

1. **锚用户自己的基线** —— App 记录你自然发每个元音时的 F1/F2，
   目标区 = 基线 × 男女比值。不用额外步骤，正常发声就有基线。
2. **锚人口平均值** —— 就是现在的做法。简单，但对偏离平均的人够不到。

> 目前采用的是第 2 种（用户选的）。
> 第 1 种更贴合「在保持元音可辨认的前提下整体往前抬」这个目标，
> 但要改训练流程，留着以后做。

### 附带发现：身份和女性化在 F1/F2 上纠缠

「女性化目标」落在元音空间的前面，所以用户走向目标时，
识别标签会跟着漂。普通话单元音挤得比英语紧，问题更明显：

| 识别参照 | 啊 | 鹅 | 衣 | 乌 | 鱼 | 哦 |
|---|---|---|---|---|---|---|
| 只比男性参考位置 | ✓ | ✗ | ✓ | ✗ | ✗ | ✗ |
| **两个参考点都参与** | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

做法是每个元音有两个参考点（自然位置 + 女性化目标位置），
但目标点要额外付 90 Hz 的代价（`GOAL_MATCH_PENALTY`）：

| | 在目标位置认对 | 真实录音稳定段帧正确率 | 典型男性 /啊/ |
|---|---|---|---|
| 只比自然位置 | 2/6 | 76.3% | ✓ |
| **加 90 Hz 代价** | **6/6** | **76.3%** | ✓ |

代价不能省：「两个点取更近的」会把本该属于别人的读数吸过来
（鹅被认成乌、衣被认成鱼，帧正确率从 65% 掉到 36%）。
也不能用「离目标 < 90 Hz 就认它」的门限 —— 典型男性 /啊/
（730/1090）离「哦的目标」（700/1100）只有 43 Hz，会被误判。

### 还剩一个真实的限制

用户的「啊」（实测 419/1454）离人口平均值太远，
任何人口参照的分类器都会判错（实测认成「鹅」）。
要解决只能靠个人基线，或者靠 F3（圆唇信息）——
而 F3 在 11 kHz 分析域上不够准。

### 真机端到端验证（Note 20 Ultra，Android 13）

不只比离线录音 —— 直接抓 **App 自己录的音频**，
和 App 界面显示的值逐帧对照：

1. `am broadcast -a com.vera.pinkvoice.DUMP_AUDIO` 让 App 把最近 20 秒
   的原始音频（48 kHz）导出来
2. 用**真 Praat** 分析这段 WAV
3. 和同时刻的 App 显示日志（`SHOW f1=… f2=…`）按墙钟时间对齐

结果：

| | 结果 |
|---|---|
| **显示跳变率** | **0.0%**（18 次取值变化，0 次超过 10%） |
| 稳定段平均 \|ΔF1\| | **24 Hz** |
| 稳定段平均 \|ΔF2\| | **49 Hz** |

> 注意：**不能逐帧比全部帧**。Praat 自己相邻帧的变化中位就有 24 Hz、
> P90 达 268 Hz（最大值 1818 Hz）—— 用户快速换音时，
> 两边的 150 ms 窗口根本跟不上。只看 App 显示稳定的帧才有意义。

端到端的 24/49 Hz 和离线测试的 8–49 Hz 一致 ——
说明**分析层在真机上也是对的**，不只是离线复刻对。

另外这次真机上还验证了**双参考点识别**的价值：
用户的读数在 F1 891–1076（正好是「啊」的女性化目标区 1000±72 附近），
识别稳定给出「啊」。用旧的「只比自然位置」的方案，
这个位置会被认成「鹅」或「哦」。

## 17. 还没做的

- **共振峰轨迹**（LTCS）：把每帧的谱按时间累积画二维图，
  一眼看出共振峰怎么走
- **共振峰的帧间跟踪**：现在是每帧独立选峰，
  真实跟踪器会利用帧间连续性来抑制伪根
- **F3/F4**：16 kHz 分析域对 F3 偏高的人（女声）不够准，
  需要 48 kHz 另开一条支路
- **虚实检测**：见 `docs/voice-quality-detection.md`
  （那篇是更早的方案，LTAS 那条路还没实现）
