# 声音虚实检测 —— 技术方案

> 状态：**方案设计，尚未实现**。
> 记录日期：2026-11-19。
> 目的是在动手前把「测什么、怎么测、怎么验证」想清楚，
> 尤其是不容易翻车的部分（个体差异、验证数据）。

---

## 1. 要解决的问题

「虚声」和「实声」是声乐/嗓音训练里的概念：

| | 虚声 | 实声 |
|---|---|---|
| 听感 | 空、飘、薄、没根 | 结实、集中、有支撑 |
| 喉部 | 放松、气多、闭合不全 | 适度收紧、声带闭合好 |
| 共鸣 | 口腔/头腔为主，散 | 胸腔+咽腔为主，聚 |
| 代价 | 长时间用嗓子累、容易疲劳 | 耐久、音量足 |

对跨性别声音训练来说，**实声是更接近目标音色的方向**，
而很多人发声习惯就是虚的。所以需要一个能**量化**的指标，
让用户知道自己当前偏虚还是偏实 —— 而不是靠耳朵和老师的主观判断。

**这不是「检测音质好坏」**，而是检测一个**可训练的维度**。

## 2. 声学上 correlate 什么

按可靠性和实现难度排序：

### 2.1 谐波噪声比 HNR（谐噪比）—— 最推荐

声带闭合越紧、激励越接近周期信号，谐波能量占比越高。

- 实声：HNR 高（比如 15–25 dB）
- 虚声：HNR 低（气声成分多，谐波间夹噪声）

**好消息：App 已经有近似现成的量。**
YIN 的 `clarity = 1 − cmnd[τ]`（CMND 最小值）本质是**归一化自相关峰**，
和 HNR 是一路的东西 —— 高周期性的帧 clarity 高。

- 复用成本：几乎为零（`PitchHistory` 里已经存了 `clarity`）
- 局限：只在**有基频的帧**上有意义；无声/气声帧 clarity 直接是 0，
  会和「很虚的气声」混淆

### 2.2 LPC 谱包络的倾斜（Spectral tilt）—— 推荐

用 LPC 求出声道传递函数的包络，看它**随频率怎么衰减**。

- 实声：低频共鸣多 → 包络陡（暗、low）
- 虚声：中高频占比高 → 包络平（亮、thin）

**为什么要用包络而不是原始频谱**：原始频谱被基频和它的谐波结构支配，
同一个 F0 下「厚」和「薄」的差别主要在包络。而且原始频谱会被
麦克风频响、蓝牙链路染色 —— 包络受影响小得多。

**成本**：需要实现 LPC（自相关 + Levinson-Durbin）。
自相关 + 递推求根大约 150 行；**只求包络不求根的话更简单** ——
包络在若干个频点上求值就能拟合出倾斜，不用解多项式。

### 2.3 F1/F0 比值 —— 后续可选

F1（第一共振峰）反映口腔开度，F1/F0 是跨性别声音研究里
最常引用的「听感性别」指标。

- 和共振峰分析共用同一套 LPC 基础设施
- 但它测的是「音色/性别感」，和「虚实」是**正交**的维度 ——
  混在一起会让指标含义模糊

**建议：作为独立的第二期功能，不要塞进「虚实」这一个数里。**

### 2.4 不建议用的

- **绝对音量/RMS**：虚实和响度无关，反而容易诱导用户「喊大声」
- **抖动 jitter / 微扰 shimmer**：测的是稳定性，不是虚实
  （而且这两个指标对麦克风链路极其敏感）

## 3. 核心设计原则：相对基线，不是绝对阈值

**这是整个方案里最重要的一条。**

「实声」和「虚声」的**绝对频谱位置**在不同人之间差得极远：

- 男声 F0 ≈ 100 Hz，女声 F0 ≈ 220 Hz，谱重心天然不同
- 喉腔大小、面部骨骼、声道长度都不一样
- 手机麦克风的频响曲线 + 蓝牙链路的染色也不同

所以**任何固定的绝对阈值都是错的**。

### 3.1 做法：个人基线 + 偏离量

1. 让用户录一段「实声」参考（比如念一句元音），App 记下这段的特征向量
2. 之后的实时分析给出**相对参考段的偏离量**，而不是绝对值
3. UI 显示的是「比你的实声基准偏虚 / 偏实」

参考段可以：
- 引导用户录 3 秒（念「啊——」，最省事，元音稳定）
- 或者用 App 自己的历史：取用户最近 30 秒里 HNR 最高的那段当基准
  （更省心，但可能把「虚声峰值」当基准）

**推荐前者**（显式录参考），后者作为兜底。

### 3.2 归一化：按 F0 分层

即使有了个人基线，也要把 F0 的影响去掉：

- 用** LPC 包络的倾斜**而不是原始频谱 —— 包络本身受 F0 影响小
- 或者按 F0 分档统计（低/中/高），只在同档内比较

### 3.3 链路不变性

蓝牙 / 内置麦切换会改变频谱染色。所以：

- **基线必须和当前分析在同一条链路上录**
- 换链路（插拔耳机）时**基线作废**，要重新录
- 或者：切换时提示「请重新录一段基准」

## 4. 输出形式

### 4.1 主指标：一条 -1..+1 的轴

```
虚 ←────────── 0 ──────────→ 实
   -1        （你的基准）      +1
```

- 0 = 和你录的基准一样
- 负 = 比你基准更虚
- 正 = 比你基准更实

### 4.2 怎么合成

不要把多个特征直接平均 —— 它们的尺度和可靠性不一样。建议：

```
虚实分数 = w1 × z(HNR) + w2 × z(tilt)
```

其中 `z()` 是**相对个人基线的标准化值**（比如减基线均值再除以基线标准差）。
权重先给 0.5 / 0.5，等有标注数据再调。

### 4.3 稳定化

单帧的值抖动很大（清音、爆破音、换气都会影响）。所以：

- 帧率：16 ms（和现有分析支路一致）
- 显示用 **200–300 ms 的滑动中位数**
- 曲线画 1–2 秒的平滑趋势，不画原始帧值

### 4.4 UI 放哪

**建议**：读数卡里加一个「虚实」小卡片（和音高、响度并列），
显示当前分数 + 一个横向指示条。
曲线**暂时不加** —— 曲线区已经很挤（音高 + 音域标签 + 频率轴），
再加一条会看不清。

## 5. 实现路径

### 阶段一：只用现成信号（~150 行）

**目标：先验证「HNR/clarity 能不能区分虚实」这个假设。**

新增 `VoiceQualityAnalyzer`：
- 输入：YIN 每帧的 `clarity` + `rms` + `hz`
- 滑动窗口（~3 秒）统计：
  - voiced 帧的 clarity 中位数 → `hnrProxy`
  - voiced 帧占比 → `voicedRatio`（虚声时气声多，这个会低）
- 输出一个 0..1 的「结实度」

**同时加一个调试界面**：显示这两个数的实时值，
这样录一段虚声、一段实声，能立刻看出有没有区分度。

> **这一步的价值**：如果 clarity 和 voicedRatio 就能区分虚实，
> 后面 LPC 那套都可以不做。**先验证假设，再写 DSP。**

### 阶段二：加 LPC 谱倾斜（~250 行）

- 自相关 → Levinson-Durbin → LPC 系数（阶数 12–16）
- 在 200–4000 Hz 之间取若干频点求包络值
- 拟合倾斜（dB/octave 或简单的线性回归）
- 和 HNR 合成虚实分数

### 阶段三：参考段录制 + UI（~200 行）

- 引导录 3 秒基准（复用现有的录音缓冲）
- 存基线特征（`Prefs` 存几个 float 就够）
- 读数卡 + 指示条
- 换链路时提示重录

## 6. 验证 —— 这是最难的部分

**没有标注数据，这个功能没法验证。**

### 6.1 需要什么数据

同一个人，分别用「实声」和「虚声」念**同一句话**，各录 10–20 遍。
最好再找 3–5 个人（不同音域）重复。

**难点**：标注「虚/实」本身是主观的。只有**同一个人在两种状态间切换**
的对比最可靠 —— 因为它排除了个体差异。

### 6.2 怎么拿到

- 找一位有声乐/嗓音训练背景的人当「标准」
- 或者退一步：让普通人按指导念「实声」（喉部收紧、音量足）和
  「虚声」（放松、气声、飘），各录几遍
- 我自己也可以录（用手机的录音 app 录 wav，push 到设备）

**最低可行版本**：我 + 用户两个人，各录「虚」「实」各 10 段，
先看看指标能不能分开。

### 6.3 怎么验证

1. **可分性**：把两组数据画在同一个图上，看重叠多少
   - 用 AUC 或者简单的「同组内距离 vs 跨组距离」
   - 如果 AUC < 0.7，说明特征没用，得换指标
2. **稳定性**：同一状态下重复录音，指标波动多大
   - 波动必须明显小于两组之间的差距，否则用户看不到变化
3. **抗干扰**：
   - 换麦克风（内置 ↔ 耳机）后，同一段的指标变化有多大
   - 背景噪声（空调、街道）对指标的影响
   - 说话内容（元音、语速）对指标的影响

### 6.4 离线验证脚本

不用等 App 做完就能验证假设：

1. 写一个**离线**分析脚本（Python 或 Kotlin 单测）
2. 输入：wav 文件 → 输出：clarity 统计、voicedRatio、（第二阶段）谱倾斜
3. 用录好的「虚/实」数据集跑，看能不能分开
4. **分不开就不做** —— 省下后面所有工作

## 7. 风险清单

| 风险 | 严重度 | 应对 |
|---|---|---|
| 特征根本区分不了虚实 | **致命** | 先做离线验证脚本，分不开就停 |
| 主观标注不可靠 | 高 | 同一人两种状态对比；找专业标注 |
| 麦克风/蓝牙染色盖过差异 | 高 | 用包络不用原始频谱；基线和分析同链路 |
| F0 变化被误判为虚实变化 | 中 | 用包络；或按 F0 分档 |
| 元音内容主导短时结果 | 中 | 300 ms 中位数；建议念元音 |
| 用户理解不了「虚实」 | 中 | 配文字说明和引导录音 |
| 指标被用来「追求数值」而不是改善音色 | 低 | 文案上强调这是参考不是评分 |

## 8. 工作量估算

| 阶段 | 内容 | 行数 | 依赖 |
|---|---|---|---|
| 0 | 录「虚/实」对照数据 | — | 需要人配合 |
| 0 | 离线分析脚本 + 可分性检验 | ~200（Python） | 需要数据 |
| 1 | `VoiceQualityAnalyzer`（只用 clarity/rms） | ~150 | 阶段 0 验证通过 |
| 1 | 调试界面（实时显示中间量） | ~80 | |
| 2 | LPC + 谱倾斜 | ~250 | 阶段 1 不够用时 |
| 3 | 参考段录制 + 读数卡 UI | ~200 | |
| **合计** | | **~880** | |

**和共振峰分析（~600 行）比，虚实检测更依赖验证数据而不是代码。**
这也是它应该排在共振峰前面的原因 —— 它更有价值，但**先做验证脚本**，
别一上来就写 DSP。

## 9. 建议的第一步

1. **录数据**：我和你各录「虚」「实」各 10 段同一句话（用手机录音，存 wav）
2. **写离线脚本**：wav → clarity 统计 / voicedRatio / 简单谱倾斜
3. **看图**：两组能不能分开
4. **结论**：
   - 能分开且稳定 → 按阶段 1 开始做
   - 分不开 → 先换特征（试 LPC 倾斜、HNR 的更标准算法），
     还不行就放弃这个方向

**在第 3 步看到结果之前，不写 App 里的代码。**
